# Isolated runtime recovery rehearsal

[snapshot-runtime.py](../scripts/snapshot-runtime.py) proves logical PostgreSQL, committed Git and artifact restoration. [rehearse-recovery.py](../scripts/rehearse-recovery.py) additionally creates a pending **mock fixture inside a restored QA installation**, exports that installation, and resumes the same fixture in a second fresh installation. This does not interrupt or simulate destruction of the real host.

Run from the Windows umbrella with the supported Python environment and the existing ordinary Ubuntu WSL worker environment:

```powershell
python scripts/rehearse-recovery.py --snapshot REPORTED_COMPLETE_SNAPSHOT_ID --allow-isolated-runtime
```

The command accepts a generated snapshot identifier, not an arbitrary restore path. It verifies the existing private snapshot before creating resources. No fresh source snapshot is taken and no source run is paused, cancelled or resumed. The source snapshot must contain only terminal or paused/drained runs. Historical runs are not resumed for execution; the copied orchestrator may honor existing cancellation requests or expired deadlines and cancel a previously paused historical run inside QA. A source snapshot with dispatchable runs is refused. Provider credentials, OAuth files, shell environment secrets and source mounts are never copied.

## What the rehearsal does

1. Inspect only the existing API/orchestrator/frontend image IDs, use the snapshot's pinned PostgreSQL image and the locked Redis image, and measure Docker memory/container count. A generation has five containers capped at 1.75 GiB total and one CPU each; creation refuses insufficient measured headroom. Docker settings are not changed.
2. Create generation A on its own labelled `--internal` Docker network with **no published host ports**, no bind mounts and fresh anonymous PostgreSQL/Redis image volumes. Restore the trusted PostgreSQL dump and all artifact bytes. Restore all Git refs/HEAD into new repositories below the ordinary WSL user's ext4 `~/ai-factory/recovery-rehearsals/<namespace>/stage-a` directory.
3. Generate new private database passwords, admin/orchestrator/worker tokens and Redis ACL credentials. Deliver them through private files/archive stdin before container start. Application Docker argv/env contain file references and nonsecret connection details only. Relocate only copied project metadata and register one fixed, harmless Python check. Telemetry and LangSmith tracing are disabled.
4. Through the actual QA API, create mock developer/reviewer/integrator definitions, a bounded policy and a DAG for file creation, registered test, independent review, Git commit and integration. Start the actual orchestrator and stop only the new QA generation after a never-claimed execution, PostgreSQL checkpoint and outbox entry exist. The fixture's provenance is QA-only; it was not unfinished work recovered from the original host.
5. Export a private generation-A logical dump, Git bundles and original artifact bytes with checksums. Preserve A. Create generation B with fresh PostgreSQL, empty Redis and another ext4 root. Restore A, relocate only this controlled never-spawned fixture, and compare checkpoint counts/execution/outbox IDs before replay.
6. Restart B's actual orchestrator. Its durable outbox reconstructs Redis delivery. Execute those jobs with the production WSL `Executor`, `ExecutionSupervisor` and `ApiClient`, forcibly selecting only `MockAdapter`. Verify successful operations, review/test/commit/integration evidence, original artifact SHA-256 values, frontend serving, and unchanged QA `main`. Duplicate terminal deliveries are acknowledged without invoking the adapter again.
7. Invoke production reconciliation against a missing local supervisor journal. Require `EXECUTION_UNCERTAIN` before any provider is spawned. Missing journals do not establish process death or authorize restarting an uncertain CLI.

The QA HTTP/Redis bridge uses fixed allowlisted Docker-exec stdin helpers because production host-worker connections require loopback while this rehearsal deliberately publishes no host ports. It exercises real API leases/events/artifacts and real Redis stream read/ack operations, but does **not** test production host-network connectivity, the detached worker consumer process, or native Codex/Claude authentication/session recovery. That limitation is included in the report.

## Isolation and evidence

Container names are `adf-recovery-<generated eight hex characters>-<a|b>-<service>`. Every mutation checks the generated namespace and ownership label. Network inspection must prove an internal network with only its generation's attachment; container inspection must prove no published ports/privileged mode/bind mounts and the planned CPU/memory caps. Only fresh anonymous image-managed infrastructure volumes are accepted. There is no arbitrary shell, cleanup, user-supplied command, provider API call or global security setting change.

Private reports and request/credential files remain in ignored `.bootstrap/runtime-recovery/<namespace>/`. POSIX roots/files use `0700`/`0600`; Windows files inherit the private umbrella user's NTFS ACL, which this script does not certify or modify. Failed partial generations are preserved. No resource/file/volume is deleted. Generation A's own containers are stopped during export; successful generation B remains available for review.

`report.json` is written only after actual runtime gates pass. It records image IDs, measured resource headroom, fixture IDs, restored checkpoint/outbox identities, successful execution operations, original artifact verification, integration/main status and the reconciliation/networking limitations. `failed-report.json` retains safe diagnostics with readiness false. Credentials, prompts, source code, stdout and arbitrary API response bodies are never printed. [test_recovery_rehearsal.py](../tests/test_recovery_rehearsal.py) covers namespace/ownership refusal, CLI secret absence, private archive ownership, resource refusal, HTTP/Redis allowlists, malformed RESP and fixed WSL executable/environment guards; these fixtures do not claim a live recovery pass.

## Recovery scope

PostgreSQL checkpoint/outbox state, artifact bytes and committed Git history are authoritative for the demonstrated application recovery. Redis is reconstructed transport; saving its previous queue state is not needed for this controlled never-spawned fixture. Langfuse is independent observability storage and needs its own PostgreSQL/ClickHouse/object-store backup if telemetry retention is required. Neither an existing Langfuse backup nor provider credentials are fabricated for this rehearsal.

A full physical host loss with an in-flight native CLI remains outside this proof: the snapshot excludes worker journals and uncommitted worktrees. An uncertain execution must stay fenced until an operator supplies accepted reconciliation evidence; automatic relaunch is unsafe. The dedicated-account/provider permission and production connection gates are assessed separately. Safe fencing and refusal to relaunch uncertain executions without accepted evidence remain required. Additional proof of native provider-session continuity across physical host loss is subsequent recovery hardening; it is not introduced here as a new MVP gate. Retention, encryption/off-host copies, RPO/RTO, Langfuse restoration and automated disaster orchestration are subsequent operations hardening, not facts established by this isolated mock pass. See [backup](operations-backup.md), [reliability](reliability.md), [security](security.md) and the preserved [SPEC](../SPEC.md).

PostgreSQL documents custom-format dumps and strict restore transactions: [pg_dump](https://www.postgresql.org/docs/18/app-pgdump.html), [pg_restore](https://www.postgresql.org/docs/18/app-pgrestore.html). Git bundles preserve referenced history rather than journals/working-tree files: [git-bundle](https://git-scm.com/docs/git-bundle). Image/service compatibility is established by the recorded local image IDs and actual QA evidence, not inferred from newer upstream documentation.
