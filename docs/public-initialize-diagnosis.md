# Public initialize diagnosis: read-only profile is an incompatible diagnostic boundary

October 12, 2026. **The pinned public Node/npm/app-server startup works with a new empty writable profile. The failed full-read-only-profile helper prevents mandatory SQLite and installation-ID initialization.** This is a reproduced operator-test isolation defect, not evidence that Node or the production factory is broken. The installed worker remains `0dd5ac7`; real profiles, auth/manifests, queue and services were not changed by this source diagnosis. [Sanitized evidence](evidence/public-initialize-diagnosis-2026-10-12.json) excludes raw stderr, RPC bodies and secret values.

## Causal comparison

Every case creates a new empty synthetic profile and sends exactly one `initialize`; no `initialized`, thread, model, auth/account or tool call follows. Public tools retain Python 3.12.9, Node 24.21.0 and Codex 0.157.0 with verified public hashes. The official npm symlink/package layout, factory argv, nine-name environment and Node/worker-bin/system PATH order are retained. Startup cwd is the logical `providers/codex` in an empty private overlay. Public Python/Node/npm/system roots are RO; private user/mount/PID/network/IPC namespaces exclude host routes, `/run` and `/mnt`. The parent proves isolation before startup and before the request. No real profile, default auth home, host IPC endpoint or service data is mounted.

The [official pinned launcher](https://github.com/openai/codex/blob/rust-v0.157.0/codex-cli/bin/codex.js) resolves/spawns the platform binary and preserves the supplied environment. Node, its loader, the npm package and the native binary are accessible in both profile cases. No PATH/library/mount change was needed to obtain success. The alias warning for a temporary synthetic home is nonfatal in the [pinned arg0 source](https://github.com/openai/codex/blob/rust-v0.157.0/codex-rs/arg0/src/lib.rs); the successful control also retains the bundled-bwrap fallback warning.

The [pinned config implementation](https://github.com/openai/codex/blob/rust-v0.157.0/codex-rs/core/src/config/mod.rs) defaults SQLite storage to CODEX_HOME and supports `sqlite_home`. [App-server startup](https://github.com/openai/codex/blob/rust-v0.157.0/codex-rs/app-server/src/lib.rs) requires SQLite initialization and then [installation-ID resolution](https://github.com/openai/codex/blob/rust-v0.157.0/codex-rs/core/src/installation_id.rs) before the stdio connection starts. The latter always opens the file for read/write/create and locks it, even when a valid ID exists. Redirecting SQLite alone therefore cannot make the full-RO profile compatible. These source statements and the one-change writable control establish the synthetic mechanism.

## Minimal source fix and regression

The first writable control exposed a separate cleanup defect: the pinned standalone Python lacks `os.pidfd_open`. Its unfinished result is not retroactively reconstructed. A read-only scan found zero surviving processes with the known synthetic profile mountpoints, without reading cmdline/environ or sending signals. The operator-only fix switches its two direct pidfd calls to the already implemented guarded worker wrappers. [Exact public patch](evidence/metadata-operator-pidfd-fix-2026-10-12.patch) is retained; the original used helper stays unchanged and the corrected copy is separate. Existing PID/start-tick/namespace checks, signals, FD close and shutdown bounds are preserved. No production module or dependency is modified.

The [focused worker regression](../services/runtime-worker/tests/test_shared_server.py) adds three initialize-only cases: full RO failure, SQLite-only redirect failure, and writable success. It uses existing fresh sealed/native fixtures and checksum-pinned public Node/npm inputs, actual factory args/environment, a 65 KiB aggregate output bound, and a dedicated owned SID. It deliberately removes the Python-native pidfd APIs to exercise the existing ABI fallback during actual cleanup. All three cases passed in **4.26 seconds** in a new disposable QA venv; frame-boundary and pidfd fake checks each passed2/2; Ruff and independent source review passed. Published worker source `76a78f57d7b8e5900d5c1a02fbb244b457ddab52` passed its [exact Linux CI](https://github.com/alex-kzr/adf-runtime-worker/actions/runs/38255848529): **389 tests in 144.63 seconds**. All 29 production modules and dependency locks remain unchanged, so the installed `0dd5ac7` runtime does not require an update for this test-only release.

No generic owner framework, production stderr logging, auth copying, package update, permission grant, real-owner retry or replay was added. Temporary fixture state and QA dependencies remain outside committed/runtime data. Only public test source, the minimal patch and sanitized documentation are published.
